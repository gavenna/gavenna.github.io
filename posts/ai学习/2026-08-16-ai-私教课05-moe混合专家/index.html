AI 私教课 第5课 — MoE：DeepSeek 为什么便宜
#

前置：第1课 LLM本质 / 第4课 训练原理 本课补全了一个重要缺口：FFN 子层（第 2 课讲「每层=染色」时省略了它，本课修正）

学习目标
#

  • 理解每层的完整结构：Attention + FFN 两个子层
  • 搞清 FFN 是什么（知识染色）和为什么它是参数大头
  • 掌握 MoE：路由器 + 专家、稀疏激活、训练机制
  • 理解「信息源决定参数规模」的架构逻辑

一、修正：每层 = Attention + FFN 两个子层
#

第 2 课省略了 FFN（教学缺口，本课补上）：

子层干什么token 间交互？信息源
Attention（染色）从别人那里收集信息（交流）✅prompt 内部（小）
FFN对自己收集的信息做加工（思考）❌ 独立训练库知识（巨大）

每层流程（最终版）：

① Attention：打分→归一→期望（token 间交流）→ a
② FFN：放大→过滤（负数清零）→压缩（自身思考）→ h'
③ 下一层……

为什么需要 FFN（非线性）：没有非线性，两层线性 = 一层线性（退化成线性函数）。ReLU 的负数清零 = 每层的「折弯」，让网络能表达复杂函数。

二、FFN = 知识染色（本课核心类比）
#

开关板 + 联想模型
#

向量 = 一排开关（亮 = 特征被激活）

FFN = 根据当前开关状态，触发新的联想开关：
  输入：[网络问题:亮] [高铁:亮] [信号满格:亮]
  FFN 内部有大量联想模式：
    模式1：「网络问题+满格 → 怀疑注册失败」→ 触发！
    模式2：「网络问题+高铁 → 可能切换失败」→ 触发！
    模式4：「客户姓名+天气 → 无关」→ 不触发（负数清零丢弃）
  输出：[怀疑注册:亮] [怀疑切换:亮] [业务层:亮]

三层理解（放大→过滤→压缩）
#

步骤做什么类比
① 放大准备大量联想模式（维度 ×4）先列所有可能原因
② 过滤负数清零，只留触发的联想划掉不成立的
③ 压缩浓缩回原维度形成初步判断

与 Attention 的分工
#

Attention = 收集信息（交流）——只会「抄作业」，不会产生新想法
FFN = 消化信息（思考）——根据现有状态触发新联想，产生新信息

只有 Attention：永远在复制粘贴上下文已有信息，没有推理能力
FFN 是模型「想出新东西」的地方

关键类比（我的原创）：两次染色
#

Attention = 拿「这段对话」给 token 染色（内部交流） FFN = 拿「训练库知识」给 token 染色（调取全人类规律）

FFN 参数 = 训练库知识的浓缩形态（第 1 课「压缩规律」的落点）。token × FFN 矩阵 = 当前理解 × 万千规律 = 触发联想。

三、为什么 FFN 是参数大头（信息源决定规模）
#

Attention 信息源 = prompt（几十~几万 token）→ 参数小（~12%）
FFN 信息源 = 训练库知识（万亿 token）→ 参数大（~80%）

V4：Attention ~0.2T，FFN 专家 ~1.3T

信息源多大，装它的参数就要多大。 训练库知识远比任何 prompt 大——所以 FFN 必须大一个数量级。（架构逻辑，自己推导出的）

四、MoE：把知识柜子拆成 400 个抽屉
#

传统 vs MoE
#

传统层：h → Attention → 1 个巨型 FFN（全量参数）→ 输出
MoE 层：h → Attention → 路由器选 2 个专家 FFN → 加权输出
                          （400 个专家，只激活 2 个）

路由器数学（线性层 W_g）
#

① 打分：score = h · W_g → 400 个分数（每个专家一个亲和力分）
② Top-K：选分数最高的 2 个专家
③ 门控：softmax(选中的 2 个分数) → 权重（加起来=1）
输出 = w₁ × FFN₃₇(h) + w₂ × FFN₉₂(h)

每层重新路由
#

同一个 token 走 32 层：
  第 1 层 → 专家 92+37（词义层）
  第 2 层 → 专家 150+3（短语层）
  ……
  第 32 层 → 专家 300+45（全文逻辑层）
每层都有自己的 400 个专家，每层重新选 → 32 层共 64 个专家接力

专家粒度（修正误区）
#

误区真相
专家 = 领域（网络/前端）专家 = 计算变换模式（放大/旋转/组合）
一个答案 = 一个专家负责每层 2 个专家接力，共 64 个
400 个专家 = 400 个领域400 × 32 层 = 12,800 个中间计算器

五、MoE 训练：没有「正确专家」标签
#

❌ 不是：先算出正确答案需要哪些专家，再训练路由器匹配
✅ 而是：路由器随机初始化 → 前向选 top-2 → 算损失
       → 梯度同时更新「被选中的专家」和「路由器」
       → 选对了损失降 → 这次路由被强化；选错了 → 被削弱
       → 亿万次后，路由器自己演化出路由策略

关键：像强化学习（无标准答案，靠反馈调节），不像分类训练（有标签）。

负载均衡（辅助损失）
#

如果没有惩罚：路由器把所有 token 塞给最强的 1-2 个专家 → 其他闲置
加惩罚：损失 = 预测错误 + 路由不均衡惩罚
→ 路由器被迫分散 token → 每个专家被迫学习不同领域
→ 训练后专家自然分化出专长（数学/代码/协议……）——不是人为指定的

六、省钱本质：知识量与计算量解耦
#

总参数 1.6T（装全部知识，400 个专家各存所长）
激活参数 49B ≈ 3%（每次只算被选中的专家）

知识量 = 1.6T（大，不降）
计算量 = 49B（小，3%）

→ 知识容量不降，计算成本大降 —— DeepSeek 便宜的全部秘密

MoE 只动 FFN（知识染色机）：Attention（上下文染色）参数少且必须全量，不 MoE 化。

七、完整账目（60 token prompt 走一遍）
#

传统：60 token × 32 层 × 每层全量 FFN（1.6T 全部参与）
MoE：60 token × 32 层 × 每层只激活 2/400 专家（≈3% 参数）

长 prompt 流程：
  60 token 向量化 → 每层（Attention 全量 + 路由器选 2 专家）→
  32 层接力 → 「。」意图向量 → 第二层打分 → 采样 → 蹦字 → 循环

八、本课沉淀的能力信号
#

  • 抓到教学缺口：第 2 课省略 FFN → 本课补全（用户主动发现「哪里多出来一个 FFN」）
  • 原创类比：「FFN = 拿训练库给 token 染色」（两次染色：上下文色 + 知识色）
  • 架构洞察：「信息源决定参数规模」——prompt 内部染色永远比不过训练库知识染色
  • 一句话抓住本质：「还是最开始那套 + 稀疏激活约束」
