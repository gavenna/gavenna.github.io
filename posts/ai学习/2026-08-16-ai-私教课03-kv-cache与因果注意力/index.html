AI 私教课 第3课 — KV Cache 与因果注意力
#

前置：第2课 — 注意力机制与染色 教学方式：苏格拉底式。本课修正了第 2 课的一个简化（「互相染色」），并补全了「变形矩阵」这一省略步骤。

学习目标
#

  • 理解为什么上下文越长生成越慢（平方爆炸）
  • 搞清 KV Cache 缓存什么、省什么、为什么合法
  • 修正第 2 课「互相染色」为「单向因果注意力」
  • 算清 1M 上下文的内存真相

一、为什么长对话慢：平方爆炸
#

每蹦一个字，成本 ≈ 层数 × 上下文长度²
#

总点积 ≈ N层 × M个字 × L²（固定上下文时）
L 翻 10 倍 → 点积量翻 100 倍

我的公式（含动态增长，教科书常忽略的洞察）：

总点积 = N × Σ_{i=0}^{M-1} (L+i)²
       = N × [ M·L² + 2L·M²/2 + M³/3 ]（近似）
  • M·L²：固定上下文成本（大头——「每个字都要重看全部历史」）
  • 长对话烧钱根源 = L 和 M 双双增长，成本近似 L²·M

二、因果注意力：染色是单向的（修正第 2 课）
#

生成式模型只能看左边
#

位置：  1     2     3     4     5
       [世界][上][最高][的][山]  ← 「？」还没生成
位置 3（最高）只看 1~3，看不到 4~5（未来）

因为生成是逐字往右蹦的——右边的 token 还不存在，不可能被看到。

修正第 2 课的「互相染色」
#

第 2 课（简化，错误）第 3 课（生成模型真相）
每个 token 和剩下所有做点积（L²）每个 token 只和左边做点积（≈L²/2）
互相染色单向染色（右边吸收左边）
染色结果随上下文变化历史 token 表示定型，永不重算

「苹果手机很好用」：

  • 位置1[苹果] = f(苹果)，看不到手机 → 没被手机染
  • 位置2[手机] = f(苹果, 手机) → 被苹果染了
  • 「手机」的表示更丰富（看到了苹果）

三、KV Cache：让 L² 变 L 的工程利器
#

核心机制（不是近似，是精确）
#

因果注意力 → 历史 token 看不到未来 → 表示定型
→ 旧 token 的 K/V 冻结在缓存，永不重算
→ 每蹦一个字，只有新 token 走完整 N 层

每蹦一个字：

① 新 token 算自己的 Q/K/V（唯一新计算）
② 新 Query × 缓存里所有旧 K（L 次点积）← 权重要重算（第 2 课已抓出）
③ softmax + 加权综合
④ 新 K/V 存入各层缓存

没有 KV Cache： N × L² × M（平方爆炸，跑不动） 有 KV Cache： N × L × M（线性，跑得动）

工单类比：翻笔记，不重读原文
#

读完每段日志 → 结论记笔记（= 染色 + 存缓存）
新日志来了 → 只看新日志 + 翻笔记
永远不会因为读到后面，回去重读前面的原文

四、为什么每层都要存一份 KV？（我的质疑）
#

问： 不是只存第 32 层的向量就行了吗？ 答： 每一层注意力都需要「旧 token 在那一层」的 K/V。

新 token 走 N 层，每层都做一次注意力：
  第 1 层 → 需要旧 token 第 1 层的 K/V（浅层对比）
  第 2 层 → 需要旧 token 第 2 层的 K/V（稍深）
  ……
  第 32 层 → 需要旧 token 第 32 层的 K/V（最深）

新 token 在每一层处于不同理解深度，只能和「同深度」的旧 K/V 匹配。 跨层匹配无意义（见下）。

五、为什么跨层匹配无意义（我的质疑）
#

问： 数学上任何向量都能点积、归一、算期望，跨层怎么就不行？ 答： 数学可行，但数值无意义——每层数字属于不同「度量体系」。

第 1 层的 Q = 向量 × 第1层的W_Q   ← 「厘米」刻度
第 32 层的 K = 向量 × 第32层的W_K ← 「秒」刻度
5 厘米 × 3 秒 = 15 → 没有单位，没有意义

训练时模型从没见过跨层匹配（每层矩阵只和同层配合调出来的），强行跨层点积 ≈ 随机数。

同层匹配 = 同深度的理解互相比较 → 有意义。

六、补全省略的步骤：变形矩阵 W_Q/W_K/W_V
#

之前讲「染色 = 打分→归一→期望」省略了「变形」
#

每层完整流程：

输入向量
   ↓ ① 变形：× W_Q → Q（提问者）/ × W_K → K（被查者）/ × W_V → V（提供者）
   ↓ ② 注意力：Q × K 打分 → softmax → 权重 × V → 期望
   ↓ ③ 输出：染色后的新向量 → 下一层（换一套矩阵）

为什么需要变形（三角色）
#

一个 token 要同时扮演：提问者（Q）/ 被查者（K）/ 内容提供者（V）。 同一个向量不能同时当三个角色（自己问自己无信息量），所以用三个矩阵投影成三个不同「身份」。

类比：同一个人有面试官（Q）、简历（K）、实际能力（V）三个身份。

为什么每层一套矩阵
#

每层处理不同抽象深度：第 1 层词义 → 第 2 层短语 → 第 3 层句子 → …… → 第 N 层全文。 每层在自己的语义空间做匹配，所以每层需要自己的 W_Q/W_K/W_V。

七、KV Cache 的内存账（1M 上下文的真相）
#

KV Cache = token数 × 层数 × 2(K和V) × 维度 × 字节数
100万 × 32层 × 2 × 128维 × 2字节 = 16.4 GB ！！

单次对话 KV Cache 就要 16.4 GB 显存（还没算模型权重 ~65GB 和激活值）。

「支持 1M 上下文」≠「1M 随便用」：模型架构支持，但真塞满 100 万 token，显存先爆。DeepSeek 的 1M 是「能力上限」+ 峰谷定价 / 缓存命中打折 → 变相鼓励别把上下文撑满。

八、本课沉淀的能力信号
#

  • 主动写出含「L 动态增长」的成本公式（教科书常忽略）
  • 抓出第 2 课「互相染色」与第 3 课「只看左边」的矛盾 → 修正为因果注意力
  • 追问「只存最后一层不行吗」→ 每层 KV 各存一份的机制
  • 追问「跨层数学上能算啊」→ 度量体系不同，数值无意义
  • 诚实定位数学缺口：点积/期望/分布公式「懂个大概」，用直觉补足

九、三课完整链路（最终版）
#

① token 切分 → ② 向量化（embedding，训练调的）
③ 每层：变形（×W_Q/W_K/W_V）→ Q×K 打分 → softmax → 权重×V（期望）→ 染色
④ 因果注意力：只看左边 → 历史定型 → KV Cache 精确成立
⑤ N 层后取「。」意图向量 → 第二层打分 → softmax → 采样 → 蹦字
⑥ 循环：新 token 入缓存，Query 换新，重跑
